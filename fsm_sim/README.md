# 씨름 로봇 FSM 시뮬레이터 (`fsm_sim/`)

2026 IRC 씨름 로봇의 주행 FSM을 위에서 내려다본 2D 경기장에서 돌려 보는 도구입니다.
펌웨어 FSM(v1)을 그대로 옮긴 것과, 예찬의 전략 표 의도를 따라 새로 짠 FSM(v2)을 나란히 비교하고 서로 싸움 붙일 수 있습니다.

**로직·우선순위·시간값을 확인하는 용도입니다.** 물리(밀기 힘, 마찰, 홈 깊이)는 단순화했으므로 실물 성능을 보장하지 않습니다.
펌웨어(`ESP_MAIN/`)는 이 폴더 작업으로 바뀌지 않았습니다.

## 실행

| 목적 | 방법 |
|---|---|
| 화면으로 보기 | `index.html`을 브라우저로 연다 (설치 없음, `assets/robot_top.png`를 같은 폴더 기준으로 읽음) |
| 한 파일로 공유 | `python tools/build_artifact.py` → `dist/sumo-sim.html` (그림 내장, `dist/`는 커밋하지 않음) |
| 지표 모으기 | `node tools/run_batch.js '{"ourFsm":"v2","opp":"wander"}' 12` |
| v1·v2 대결 비교 | `node tools/duel.js 6` (조합마다 좌우 시작 위치 × 6경기) |

`run_batch.js`의 첫 인자는 화면의 입력 id와 값입니다 (`preset`, `ourFsm`, `opp`, `startPos`, `atkBox` 등).
v2 내부 상수는 `"__v2":{"BLUE_PUSH_MS":250}`처럼 덮어쓸 수 있습니다. 같은 시드면 결과가 같습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 시뮬레이터 전체 (화면, 경기장, FSM v1/v2, 물리, 규칙) |
| `assets/robot_top.png` | 우리 로봇 CAD 윗면 그림 (위쪽이 앞이라고 가정, 화면에서 뒤집기 가능) |
| `tools/run_batch.js` | 브라우저 없이 경기를 돌려 득점·접촉·상태 시간을 집계 |
| `tools/duel.js` | v1/v2 × 상대 행동 조합 비교 |
| `tools/build_artifact.py` | 단일 HTML로 묶기 |
| `PROMPTS.md` | 만들면서 받은 지시, 근거가 된 사실, 결정과 결과, 이어서 쓸 프롬프트 |

## 무엇이 들어 있나

- **경기장 (규정 1.7, 그림 3·4):** 2400 × 2400mm, 빨간 원 지름 700, 파란 사분원 반지름 700, 노란 홈 450 × 70 (원·사분원과 98.5mm 간격).
  시작 위치는 왼쪽·오른쪽 ㄷ자(벽에서 130mm, 300mm 선이 바닥에서 1350mm), 왼쪽은 아래쪽 벽, 오른쪽은 위쪽 벽을 본다.
- **득점 (규정 3.2):** 모든 바퀴가 빨강 3점, 파랑 2점, 5초 유지 +2점, 10초면 처음 위치, 벽 10초 접촉은 상대 1점.
- **카메라:** Raspberry Pi Camera Module 3 Wide, 수평 102°, 1920 × 1080, 핀홀 투영. 목표는 상대 색깔 통(지름 70, 높이 80mm, 규정 그림 2).
- **바닥 센서:** 네 모서리, 같은 색 3회 연속이면 확정 (펌웨어와 같음). 노란 홈은 기본으로 무시 (규정 1.7⑩).
- **FSM v1:** `ESP_MAIN/src/control/robot_fsm.cpp`, `drive_logic.cpp`, `control_config.hpp`를 줄 단위로 옮김 + 출발 기동, 360° 탐색, 홈 끼고 돌기 옵션.
- **FSM v2:** 아래 표. `index.html`의 `class FsmV2`.
- **끼임 판단:** 출력은 큰데 거의 안 움직이면 `stalled`. 실물 V2에서는 IMU(MPU6050)·모터 전류로 판단하는 상황 입력에 해당한다.

### FSM v2 우선순위

| 순위 | 상황 | 행동 |
|---:|---|---|
| 1 | 정지·고장·SW1 | 브레이크 |
| 2 | 앞뒤 모두 홈 | 150ms 정지 → 마지막에 들어간 쪽 반대로, 1.5초마다 방향 전환 |
| 3 | 뒤 센서만 홈 | 전진 탈출 |
| 4 | 빨강 (앞) | 추적 중: 원 가장자리를 끼고 돌며 추적. 밀기 중: 200ms 더 밀어 상대를 넣음 |
| 5 | 파랑 (앞) | 추적 중: 뒤로 빠졌다가 중앙 쪽으로. 밀기 중: 250ms 더 밂 |
| 6 | 벽·끼임 | 상대가 앞에 크게 안 보이면 후진 |
| 7 | 공격 진행 | 돌진 220 → 급정지 90 → 스포크 350 → 밀기. 밀다 멈추면 빠졌다가 각도 바꿔 재공격 |
| 8 | 상대 보임 | 멈추지 않고 움직이며 조향, 상대 이동 방향으로 150ms 앞질러 겨눔 |
| 9 | 방금 놓침 | 마지막으로 본 쪽으로 0.7초 회전 |
| 10 | 출발 | 중앙 쪽(로봇 기준 왼쪽)으로 틀어 사선 전진 |
| 11 | 안 보임 | 한 방향 360° 회전, 한 바퀴 돌아도 없으면 잠깐 전진 |

뒤로 빠지는 동작(탈출·파랑·벽·밀기 후)은 센서가 홈에서 벗어났고 상대가 보이면 회전을 건너뛰고 바로 재공격한다.

## 지금까지 결과 (가정값 기준, 좌우 시작 위치 × 6경기 평균)

| 대결 | 우리 득점 : 실점 |
|---|---|
| v1 (최적 + 끼고 돌기) vs 무작위 배회 | 29.0 : 0.1 |
| v2 vs 무작위 배회 | 32.6 : 0.0 |
| v2 vs v1 | 6.1 : 2.4 |

주요 발견: 펌웨어의 `ATTACK_BOX_HEIGHT = 420`은 와이드 카메라에서 약 150mm라 공격 시퀀스가 실행되지 않는다 (시뮬레이터 권장 200).
자세한 경위는 `PROMPTS.md`.

## 단순화·가정 (실물로 확인할 것)

- 최고 속도 1.2m/s(출력 1000‰), 바퀴 간격 250mm, 카메라는 로봇 중심에서 60mm 앞: 실측 전 가정값.
- 충돌은 원(반지름 160mm)으로 근사. 정면으로 맞서면 버티는 힘이 크고 옆·뒤는 약하며, 스포크·밀기 중이면 1.5배로 둔 **임의 규칙**.
- 홈 깊이 10mm, 센서 높이 3/10/20mm에 따른 오판정, 색 경계 혼합, 바퀴 미끄러짐은 넣지 않았다.
- 무작위 배회 상대는 홈을 피하지 않아 스스로 점수를 주므로, 득점 절대값보다 상대 비교로 본다.
