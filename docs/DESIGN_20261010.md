# 기체 설계와 기동 전략 — 2026-10-10 기록

> 설계 단계의 기록이다. 그 뒤 바뀐 것: V2 기판에 IMU(MPU6050)가 생겼지만 경기용은 뒤집힘 정지와 로그용 방향 추정에만 쓴다.
> 리어리프트 공격·턴과 외부 서버 영상처리는 **구현하지 않았다.** 스타트 정렬은 11/10에 "시작 루틴"(왼쪽 45° → 직진 2초 → 왼쪽 90°)으로
> 구현했다가 대회 마지막 날(11/13) 껐다. 급제동 뒤 상대 아래로 넣는 공격은 11/10 "포크 공격"으로 구현했다. 최종 기동은 [루트 README](../README.md)의 "경기 펌웨어"와
> [회고](../IRC2026_RETROSPECTIVE.md)가 기준이다.

이 절은 제작 전 기구 설계와 경기 전략의 기준을 기록한다. 사진으로 분석한 다른 팀 로봇의 치수는
공개 도면이 아닌 원근 보정 기반 추정값이며, 아래 기동 시간·거리·출력은 실물 시험 전에는 확정값으로
사용하지 않는다. 현재 생산 펌웨어가 아래 모든 기동을 구현했다는 뜻도 아니다.

## 비교 기체에서 얻은 기준

| 구분 | 추정 휠베이스 | 관찰한 설계 의도 |
|---|---:|---|
| 비교 로봇 1 | 약 110mm | 짧은 휠베이스와 전방 모터 배치로 일반 탱크턴과 전방 하중을 확보 |
| 비교 로봇 2 | 약 170mm | 모터를 전방으로 기울여 무게중심을 앞에 두고, 큰 회전에는 뒤를 들어 앞바퀴만으로 회전 |
| 비교 로봇 3 | 약 140mm | 넓은 바퀴와 네 모터 직결로 회전 효율보다 구동력을 우선 |
| 이전 자작 기체 | 180mm | 31mm 폭의 연한 바퀴와 긴 휠베이스가 결합되어 제자리회전 시 심한 횡끌림·변형·털림 발생 |

사진 추정값은 설계 비교에만 사용한다. 이전 기체의 180mm와 실제 털림은 확인된 경험값이므로 새 기체의
휠베이스 결정에서 사진 추정보다 우선한다.

## 확정한 기본 기구 방향

- 휠베이스는 가변형 대신 **129mm 고정**으로 확정한다.
- 좌우 바퀴 중심거리는 외폭 약 300mm와 바퀴 폭 35mm를 가정해 약 265mm를 목표로 한다.
- 바퀴는 우선 외경 약 60mm, 폭 35mm, 식품 몰드용 Shore A40 실리콘을 기준으로 한다.
- 이전 180mm에서 129mm로 줄이면 기하학적 횡슬립 거리는 약 28.3% 감소한다.
- 한 바퀴가 제자리 360도 회전할 때의 횡방향 이동량 근사는 `pi * 휠베이스`이므로,
  180mm에서는 약 565mm, 129mm에서는 약 405mm다.
- 단순 비교에서 `휠베이스 / 좌우 중심거리`는 약 `129 / 265 = 0.487`이다.
- 120mm는 회전성은 더 좋지만 전방 오버행과 피칭 부담이 커지고, 140mm는 앞축 편중과 횡끌림이
  증가하므로 두 값 사이에서 검토한 뒤 129mm를 최종 고정값으로 선택했다.
- 모터는 움직이는 장력 조절 구조로 만들지 않는다. 벨트 장력은 별도 아이들러 구조로 조정한다.
- 하판과 모터 고정부·사이드 프레임, 전방 스키드는 6061 알루미늄을 사용한다. 힘이 작은 고정 파트는
  무게와 가공비를 줄이기 위해 3D 출력물을 우선한다.
- 사이드판과 힘을 받는 모터 고정부는 현장 보유 자재에 맞춰 **6061 5T를 유지**한다. 하판은 전면을
  채운 판이 아니라 트러스 형상으로 경량화한다. 4T는 별도 구매와 재고 문제 때문에 이번 제작에서 쓰지 않는다.
- 모터 고정부는 고정형이며 슬롯으로 움직이지 않는다. 레이저 절단판에는 슬롯 접시가공을 기대하지 않고,
  모터와 풀리 사이의 볼트 머리 간섭은 접시머리 볼트와 별도 형상 검토로 해결한다.
- 휠 축은 F608ZZ 계열 플랜지 베어링과 내경 8mm 축을 기준으로 한다.

## 확정한 벨트 구동계

두 구동 구간 모두 HTD5M 20T 풀리, 피치 5mm, 벨트 폭 15mm를 사용한다. 20T 풀리의 피치원은
`100 / pi = 31.83099mm`이며, 풀리 외경이나 톱니 뿌리원을 벨트 길이 계산에 대신 사용하지 않는다.

| 구간 | 중심거리 | 구매 벨트 | 아이들러가 없을 때 피치 길이 | 용도 |
|---|---:|---:|---:|---|
| 전륜-후륜 | 129mm | 360mm | 358mm | 좌우 각 측의 두 바퀴 연결 |
| 모터-전륜 | 79mm | 260mm | 258mm | 높은 위치의 모터에서 전륜으로 전달 |

벨트 길이는 같은 20T 풀리 두 개일 때 `L = 2C + 100mm`로 계산한다. 구매한 260/360mm 벨트는 각각
아이들러로 약 2mm의 추가 피치 경로와 초기 장력을 만든다. 모터는 장력 조절을 위해 슬라이드하지 않는다.

모터-전륜 260mm 구간의 현재 기준은 다음과 같다.

- 아이들러는 608 계열 `8 x 22 x 7mm` 베어링과 M8 볼트를 사용한다.
- 위쪽 풀리 중심 기준 이론적인 무장력 위치는 왼쪽 18.249mm, 아래 36mm다.
- 현재 검토 STEP은 왼쪽 17.9255mm, 아래 35mm이며 올바른 피치원으로 계산한 경로는 약
  260.169mm다. 약 0.065%의 초기 간섭량이므로 장력 위치 후보로 사용할 수 있다.
- 추천 M8 슬롯은 폭 9mm, 전체 길이 16mm, 중심 이동량 7mm다. 중심 위치를 왼쪽 17~24mm
  범위로 두면 17mm 쪽은 장력을 늘리고 24mm 쪽은 조립 여유를 만든다.
- 슬롯에는 외경 18mm 이상 평와셔를 사용하고, 슬롯 외곽에서 판재 끝까지 최소 5mm, 가능하면 8mm
  이상의 살을 남긴다.
- M8 볼트는 베어링 내륜과 맞는 비나사부가 베어링 폭을 지나도록 길이와 반나사 구간을 확인한다.
- 구하기 어려운 스페이서는 3D 출력하되, 베어링 내륜을 누르는 면이 외륜이나 실드와 간섭하지 않게 한다.

[`mechanical/belt/`](../mechanical/belt/)에는 피치선 검사용 DXF, 1mm 단순 벨트 외형, 슬롯 DXF,
치수 그림과 현재 STEP 검토본을 보관한다. STEP 검토본은 제작 승인본이 아니다. 현재 파일에는
`Ø31.183mm` 원이 들어 있어 `Ø31.831mm` 피치원과 숫자 순서가 다르고, 아이들러 주변 벨트 경계도
R10~R11로 베어링 안쪽에 놓여 있다. 최종 물리 외형은 베어링 표면 R11 바깥쪽인 R11~R12에 두고,
벨트 길이는 별도의 피치선으로 검증해야 한다.

회전 저항을 단순 쿨롱 마찰로 보면 저항 모멘트는 대략 다음과 같다.

```text
M_scrub ~= mu_y * W * L / 2
```

다만 실제 기체는 앞축 하중이 크므로 회전 중심이 앞축 쪽으로 이동하고 가벼운 뒤축이 더 많이 미끄러질
수 있다. 따라서 위 식은 균등 하중 기체의 비교식이며 실제 저항을 그대로 보장하지 않는다. 넓고 부드러운
실리콘 타이어에서는 단순 마찰 외에 횡변형, 히스테리시스, 점착-미끄러짐 반복이 털림을 만든다.

## 무게중심과 축 하중

현재 무게 추정에서 전방에 배치되는 주요 부품은 모터 두 개 약 1,090g, 모터 브래킷 두 개 약 400g,
배터리 약 180g, 전방 슬라이드 약 200g으로 합계 약 1,870g이다. 이는 4,500g 기체의 약 41.6%다.
실제 위치가 확정되지 않았으므로 정확한 무게중심은 Fusion의 부품별 무게중심 좌표로 다시 계산해야 한다.

앞축을 `x=0`, 뒤쪽을 양수로 두면 다음 식을 사용한다.

```text
x_CG = sum(m_i * x_i) / sum(m_i)
앞축 하중 비율 = 1 - x_CG / 휠베이스
뒤축 하중 비율 = x_CG / 휠베이스
```

129mm 휠베이스에서 무게중심이 앞축 뒤 약 42mm라면 앞축 약 67.4%, 뒤축 약 32.6%가 된다.
설계 목표는 앞축 약 65~70%, 뒤축 약 30~35%다. 4.5kg 기준 앞축 약 2.93~3.15kg,
뒤축 약 1.35~1.58kg 범위다. 앞축이 70%를 크게 넘으면 전방 스키드는 잘 눌리지만 후륜 접지와 착지
안정성이 부족할 수 있다. 배터리는 최종 계측 후 앞뒤 위치를 조절할 수 있게 고정한다.

무게중심 높이는 약 60mm를 초기 목표로 한다. 모터 두 개와 배터리는 전륜 위쪽에 집중하고, 약 110g의
컬러타워도 전륜 위 높은 위치에 놓아 리어리프트 제동 기동에 활용한다. 반면 PCB, 라즈베리파이와
모터드라이버는 중앙·하부에 배치해 과도한 전복성을 억제한다. 모터 축과 전륜 축의 79mm 간격은 벨트
규격뿐 아니라 전체 무게중심 높이에 직접 영향을 주므로 완성 CAD의 질량 특성으로 다시 확인한다.

경기 중량 제한은 4,500g이며 측정 허용범위를 포함한 절대 상한은 4,545g으로 관리한다. 허용범위는
설계 여유가 아니므로 CAD 목표는 4,500g보다 충분히 낮게 둔다. 5T 6061 사이드판은 유지하고 트러스와
불필요한 면적을 줄인다. 출력물은 낮은 하중의 마운트와 스페이서에 사용하며, 전방 슬라이드 약 200g,
모터 두 개 약 1,090g, 배터리 약 180g, 컬러타워 약 110g처럼 실제 계측값이 있는 항목을 우선한다.
608 베어링, 샤프트 칼라 8개, 배터리 벨크로, M8 너트·와셔, 스위치와 비상정지 스위치, 커넥터와
수축튜브는 누락되기 쉬운 항목으로 별도 계상한다.

축 하중은 완성 기체에서 앞바퀴 두 개를 저울에 올리고 뒷바퀴는 같은 높이의 받침에 둔 상태로 측정한다.
반대 축도 같은 방식으로 확인하고 두 측정값의 합이 전체 중량과 맞는지 검사한다.

## 전방 스포크와 스키드

전방은 낮은 침투부와 급경사 상승부를 결합한 2단 형상을 우선한다.

- 첫 구간: 바닥 기준 약 30도, 수평 길이 약 30~40mm
- 전환 높이: 약 17~23mm
- 뒤 구간: 약 65~70도
- 전환부: 상대 전방판이 걸리지 않도록 약 R5~10mm로 연결
- 전환부 아래에는 충격과 굽힘을 받는 보강을 둔다.

30도 구간은 급제동 시 바닥을 스치며 상대 아래로 들어가는 역할을 하고, 이미 상대 전방 하중을 줄인 뒤
65~70도 구간이 빠르게 들어 올리는 역할을 한다. 70도 단독 경사는 초기 침투에서 벽처럼 작용할 수 있다.
스포크 끝은 경기장 표면을 손상시킬 정도로 날카롭게 만들지 않으며 실제 규정과 표면에서 확인한다.

## 바닥 센서의 기구 배치

바닥 센서는 총 네 개를 유지한다. 전방 좌우 두 개는 독립적으로 경계를 먼저 확인하고, 후방 두 개는
기체 구조상 중앙에 가깝게 놓이므로 제어에서 하나의 후방 위험 그룹처럼 OR 처리할 수 있다. 후방 센서는
밀리고 있는 사실을 새로 알려도 기동이 달라지지 않는 상황이 많지만, 잘못된 후진 회피가 길어지는 경우와
상대 공격으로 후방부터 경계에 들어가는 경우의 안전 입력으로 남긴다.

충돌 시 부러질 수 있는 돌출 센서 마운트나 바퀴 뒤쪽으로 내려오는 구조는 사용하지 않는다. 기체가 들렸을
때 바퀴 다음으로 센서가 바닥에 닿지 않게 하판 안쪽에 보호하고, 3/10/20mm 센서-바닥 간격과 10mm
단차, 하부 그늘과 센서 내장 백색 LED 조건을 모두 교정에 포함한다. 센서 위치 변경은 펌웨어의 네 채널
순서와 함께 갱신한다.

## 경기 기동의 공통 우선순위

```text
1. 비상정지와 모터 명령 만료 안전
2. 위험색·경계 회피
3. 접촉 중 밀기 유지 또는 안전 이탈
4. 리어리프트 공격
5. 리어리프트 턴
6. 일반 정렬·추적·탱크턴
7. 스타트 정렬과 탐색
```

경계 센서가 위험을 확인하면 모든 공격·리어리프트 기동보다 먼저 회피한다. 현재 V1은 IMU, 엔코더,
거리센서, 전류센서를 사용하지 않으므로 자세를 직접 확인했다고 가정하지 않는다. V1에서 리어리프트를
시험한다면 카메라 목표 정보와 제한된 시간 기반 단계로 시작하고, 출력 상한을 낮춘 실물 시험으로 시간을
결정한다. 센서를 추가하는 V2 전략과 V1 구현을 혼동하지 않는다.

## 스타트 정렬 기동

우리 시작점, 경기장 중앙, 상대 시작점이 일직선이라는 경기장 배치를 이용한다.

```text
우리 시작점 -> 경기장 중앙 -> 상대 시작점
```

1. 설치 시 정해진 기준 방향을 사용한다.
2. 시작 후 중앙과 상대 시작점이 놓인 선으로 우선 정렬한다.
3. 카메라에서 상대를 확인하면 일반 추적으로 전환한다.
4. 상대가 즉시 보이지 않으면 중앙 방향의 제한된 이동과 탐색을 수행한다.

목적은 시작 직후 불필요한 전방위 탐색을 줄이고 상대가 있을 가능성이 가장 높은 선을 먼저 점유하는 것이다.
실제 시작 배치 오차와 상대의 즉시 회피를 고려해 장시간 직진을 고정 명령으로 사용하지 않는다.

## 일반 추적과 공격

기존 FSM의 기본 공격 흐름은 다음과 같다.

```text
탐색 -> 목표 확인 -> 정렬 -> 접근 -> 돌진 -> 급정거 -> 스포크 삽입 -> 밀기
```

현재 코드의 돌진 220ms, 브레이크 90ms, 삽입 350ms는 실물 검증 전 초기값이다. 카메라의 상자 중심으로
방향 오차를 판단하고, 거리센서가 없는 V1에서는 상자 크기를 실제 거리의 대용값으로 교정해야 한다.

## 리어리프트 공격

상대가 설정 거리 안에 있고 방향이 충분히 일치할 때, 전진 가속 뒤 강한 제동으로 뒤축 하중을 줄이고
전방 스포크가 바닥을 스치며 상대 아래로 들어가게 하는 공격이다.

```text
정렬 -> 전진 가속 -> 짧은 강제 제동 -> 스포크 하강·침투 -> 양쪽 전진 출력 -> 밀기
```

- 방향 오차가 작은 경우에만 사용한다. 초기 기준은 약 ±10~15도 이내로 두되 실측으로 조정한다.
- 제동 시점은 고정 거리 하나가 아니라 접근 속도와 영상·제어 지연을 함께 고려한다.
- 너무 일찍 제동하면 접촉 전에 뒤축이 내려오고, 너무 늦으면 스포크가 내려가기 전에 충돌한다.
- 제동 직후에는 양쪽을 전진시켜 30도 저각 구간을 상대 아래로 밀어 넣는다.
- 드라이버의 능동제동 전류와 배터리의 회생 전압 수용 여부를 실물에서 확인한다.

앞축을 기준으로 뒤축이 들리기 시작하는 단순 조건은 다음과 같다.

```text
a > g * x_CG / h_CG
```

`x_CG`는 앞축에서 무게중심까지의 뒤쪽 거리, `h_CG`는 무게중심 높이다. 예를 들어 `x_CG=42mm`,
`h_CG=60mm`라면 약 0.70g보다 큰 감속이 필요하다. 타이어 변형, 스키드 접촉, 모터 제동 특성 때문에
계산값만으로 동작을 보장하지 않는다.

## 리어리프트 턴

상대와의 방향 오차가 커서 일반 탱크턴의 횡끌림이 커질 때 사용하는 특수 회전이다.

```text
짧은 전진 가속 -> 강제 제동 -> 뒤축 하중 감소 또는 이륙
-> 앞바퀴 좌우 반대 출력 -> 목표 방향 직전에 감속 -> 뒤축 착지 -> 추적 복귀
```

뒤축이 실제로 들리면 접지 휠베이스가 거의 0이 되어 129mm 휠베이스의 횡끌림을 우회할 수 있다.
초기 사용 조건은 큰 방향 오차 약 70~100도 이상을 후보로 두되, 고정값으로 확정하지 않는다.
전방에 가속 공간이 없거나 경계가 가까우면 사용하지 않는다.

착지 시 공중에서 회전하던 뒤 바퀴가 바닥과 큰 속도 차이로 닿으면 벨트, 풀리, 샤프트, 베어링에 충격이
생긴다. 목표 각도 전에 회전 출력을 줄이고 착지 직전 좌우 속도 차이를 완화해야 한다. 앞바퀴 두 개와
전방 구조는 순간적으로 기체 전체 하중을 받을 수 있게 설계한다.

## 하나의 리어리프트 공통 단계

공격과 회전을 별개의 제동 튜닝으로 만들지 않고 공통 준비 단계를 공유한다.

```text
REAR_LIFT_PREPARE
  -> 제한된 전진 가속
  -> 제한 시간 강제 제동
  -> 목적에 따라 분기
       공격: 양쪽 전진
       회전: 좌우 반대 출력
```

V1에는 자세 센서가 없으므로 `뒤축 들림 감지 완료` 같은 조건을 현재 하드웨어의 실제 입력처럼 구현하면
안 된다. 실물 시험 전에는 이 전략을 생산 기본값으로 활성화하지 않고, 저출력 벤치 모드와 안전 지그에서
제동 시간, 이동 거리, 드라이버 온도, 벨트 충격을 먼저 확인한다.

## 외부 서버 영상처리와 로컬 폴백 전략

영상처리 부하는 가까운 전용 공유기의 로컬 네트워크에 연결된 외부 서버 PC로 옮기는 구성을 시험한다.
외부 서버는 영상 인식만 담당하고, 전략 FSM·모터 출력·바닥 경계 회피·비상정지는 계속 ESP32에서
수행한다. 외부 서버가 좌우 모터 출력을 직접 결정하지 않는다.

```text
카메라
  -> 라즈베리파이: 1280x720 저지연 영상 송출
  -> 전용 5GHz 공유기
  -> 유선 연결된 서버 PC: 상대 검출
  -> UDP로 목표 좌표·박스·신뢰도 반환
  -> 라즈베리파이: 원격/로컬 결과 선택 및 14바이트 UART 변환
  -> ESP32: 기동 선택과 모터 제어
```

초기 시험은 1280x720, 최대 50FPS, H.264 저지연 RTP/UDP 송출을 기준으로 한다. B프레임과 긴 수신
버퍼를 사용하지 않고, 처리 대기열은 최대 한 프레임만 유지한다. 처리가 밀리면 오래된 프레임을 끝까지
처리하지 않고 버린 뒤 최신 프레임으로 넘어간다. 서버는 필요하면 수신한 압축 영상을 재인코딩 없이
저장하고, 검출 결과와 FSM 로그는 별도로 기록한다.

서버가 반환하는 최소 정보는 다음과 같다.

```text
frame_id, capture_time, target_x, target_y,
target_width, target_height, confidence, target_count
```

서버의 1280x720 좌표는 현재 UART 규격인 1920x1080 좌표로 변환한다. 단순 전체 화면 매핑이면
`x *= 1.5`, `y *= 1.5`를 적용한다. 원격 검출기와 로컬 검출기가 각자 UART sequence를 만들지 않고,
라즈베리파이의 최종 결과 선택기가 출처와 관계없이 하나의 연속 sequence를 생성한다.

#### 원격 우선과 로컬 자동 전환

원격 서버 결과를 기본으로 사용하되 라즈베리파이의 로컬 검출기를 폴백으로 유지한다. 원격 정상 상태에서
로컬 검출기를 완전히 종료하면 장애 시 초기화 지연 때문에 즉시 전환할 수 있으므로, 카메라 스트림과
검출기를 준비한 상태로 유지하거나 낮은 주기로 대기시킨다.

```text
REMOTE_ACTIVE
  -> 원격 결과 지연 증가 -> REMOTE_DEGRADED
  -> 새 원격 결과가 120ms 동안 없음 -> LOCAL_ACTIVE
  -> 원격 결과가 5~10프레임 연속 정상 -> REMOTE_ACTIVE
```

전환 기준의 초기값은 다음과 같다.

| 조건 | 처리 |
|---|---|
| 원격 결과 나이 0~60ms | 원격 결과 정상 사용 |
| 60~120ms | 원격 불안정 상태로 기록, 최신 결과만 제한적으로 사용 |
| 120ms 이상 새 결과 없음 | 로컬 검출 결과로 즉시 전환 |
| 1초 이상 응답 없음 | 서버 완전 단절로 기록하되 이미 로컬로 운전 중이어야 함 |
| 원격 결과 5~10프레임 연속 정상 | 복구 후보, 지연과 좌표 일치 확인 후 원격으로 복귀 |

1초는 주행 중 폴백을 시작하는 시간이 아니다. 1m/s 주행에서는 1초 동안 1m를 이동할 수 있으므로 현재
ESP32 영상 신선도와 같은 120ms를 초기 폴백 기준으로 사용한다. 원격 패킷 하나만 도착했다고 즉시 복귀하면
원격과 로컬 사이를 반복 전환할 수 있으므로 연속 정상 프레임과 복구 히스테리시스를 사용한다.

원격과 로컬 출처가 바뀐 직후 약 200ms 동안은 좌표·거리 추정 차이를 고려해 리어리프트 공격과
리어리프트 턴을 금지하고 일반 정렬과 제한된 접근만 허용한다. 바닥 경계 회피, SW1 비상정지,
모터 명령 만료 감시는 영상 출처와 관계없이 항상 우선한다. 원격과 로컬 결과가 모두 오래되면 마지막
표적을 계속 추적하지 않고 목표 상실 상태로 전환한다.

#### 채택 판단 기준

이 구성은 아직 구현·검증되지 않았다. 전용 공유기를 가까이 두고 서버를 유선 연결한 상태에서 다음을
측정한 뒤 생산 전략 채택 여부를 결정한다.

- 서버 영상처리 평균 40FPS 이상, 목표 50FPS
- 촬영부터 로봇의 결과 수신까지 평균 약 30ms 이하
- 95% 지연 50ms 이하, 장시간 큐 누적 없음
- 패킷 누락 약 1% 이하
- 통신 단절 후 120ms 안에 로컬 결과로 전환
- 원격 복구 중 반복 전환이나 오래된 좌표 재사용 없음
- 서버가 끊겨도 바닥 회피와 모터 안전 기능은 정상 유지

리어리프트의 가속·제동·삽입·회전 단계는 네트워크 왕복으로 하나씩 명령하지 않는다. 서버는 목표 위치와
기동 시작 조건에 필요한 영상 정보만 제공하고, 일단 시작한 시간 기반 기동은 ESP32가 로컬에서 끝낸다.
대회에서 외부 컴퓨터와 무선 통신을 허용하는지는 실제 적용 전에 해당 연도 규정으로 별도 확인한다.
