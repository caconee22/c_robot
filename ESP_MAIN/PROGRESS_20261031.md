## 작업 경과와 근거

### 빌드 경로 수정

한글 경로 아래 firmware.map 열기에 실패해 링커가 Invalid argument로 종료했다.
`platformio.ini`의 build_dir를 `${sysenv.USERPROFILE}/.platformio/build/c_robot_current`로 지정해
현재 PC에서 해결했다. 소스·핀맵·툴체인 버전을 바꾸는 해결책은 사용하지 않았다.

### I2C 스캐너와 전원 재시험

`src/i2c_scanner_main.cpp`와 `i2c_scanner_v2` 환경을 추가했다.
기존 BoardIo로 모터 출력은 LOW를 유지한다. GPIO11/12 메인 버스와 응답한 TCA 후보
0x70~0x77의 8채널을 검사한다. GPIO14 배터리 ADC도 출력한다.
디지털 입력·내부 풀업 32회 판독, ADC 보조 판독, 오픈드레인 소프트웨어 I2C,
Wire 스캔을 비교한다. SDA/SCL을 푸시풀 HIGH로 구동하지 않는다.

초기 전원이 불안정할 때 LOW와 시간 초과를 관찰했다. 사용자가 전원·USB를 정리한 후에는
양쪽 선 HIGH와 소프트웨어/Wire 모두 주소 0x68 응답을 재확인했다.
초기 결과만으로 배선 단락이나 칩 고장을 확정하지 않는다.
ADC 4095 포화 때 출력된 약 4981mV는 실제 선로 5V 측정으로 해석하지 않는다.

사용자는 TCA 칩을 제거했다고 밝혔다. 컬러 센서 1~4는 UNKNOWN/초기화 오류 상태다.
센서 순서·실제 색 판정은 미검증이다. 배터리는 초기 약 2.2V의 battery_missing에서
이후 약 14.85V/4S로 바뀌었다. 멀티미터와 일치하는지는 별도 확인이 필요하다.
IMU 주소 0x68, WHO_AM_I 0x72, READY/dataFresh와 증가하는 샘플은 로그에서 확인했다.
이후 Wire 오류 -1/263도 발생했으므로 지속 정상이라고 확정하지 않는다.

### GUI 및 소프트웨어 스위치

- 커밋 `548bf03183ebd21a0f794e34195c9ae324d15bf7`: 일반 모터 래치를 SW1 ESTOP으로
  잘못 표시하던 GUI 수정. system_state=7, ESTOP fault 비트 또는 명시적 ESTOP 줄을 사용한다.
- 커밋 `ba68be77137fe932c3b0b94cb70f2052497cdeb1`: 사용자 요청으로 벤치 전용 SW1/SW2
  UART 명령과 GUI 버튼 추가. `BENCH_SOFTWARE_SWITCHES=1`은 벤치 환경에만 있다.
- SW2는 기존 디바운스 경유 유한 눌림·해제를 주입하며 배터리·고장·교정 시작 조건을 우회하지 않는다.
  STOP/모드 변경/요청 지연은 진행 중인 소프트웨어 SW2를 취소한다.
- SW1은 기존 영구 구동 금지·즉시 EN 차단·ESTOP 경로를 사용한다. 재부팅 전 복구하지 않는다.
  GUI는 바퀴 띄움 체크, CLI는 `--allow-drive` 조건을 사용한다.
- 해당 기능 구현 당시 호스트 벤치 344+배터리 없음 4검사, 경기용 V2 13그룹/5041검사,
  GUI 파싱·DEMO·CLI·Tk 버튼 시험 및 두 ESP32 환경 빌드가 통과했다.
  경기용 ELF에서 소프트웨어 입력 주입 심벌이 없는 것도 확인했다.
- 이후 최신 벤치를 COM9에 업로드하여 새 명령 지원을 확인했다. 사용자 로그에서 소프트웨어
  SW1 뒤 ESTOP 반복과 SW2 뒤 시작 허가 전환을 확인했다. 실제 스위치 배선·제동거리 검증은 아니다.
- 사용자 요청으로 RTS 재부팅 후 WaitingForStart, 시작 허가 0, 고장 플래그 0을 확인했다.

### 모터 미회전의 코드 분석

| 조건 | 코드 처리 |
|---|---|
| MOTOR 모드에서 DRIVE | DRIVE는 MANUAL 전용이므로 거부하면서 시험 정지 |
| STOP 후 DRIVE | 시작 허가 해제 상태라 거부, 새 SW2 필요 |
| SW2 후 MODE 재선택 | 정지 및 시작 허가 해제 |
| 소문자 sw2 또는 MODE 1 | 지원하지 않는 명령으로 거부·정지 |
| GUI 방향 버튼에서 손 뗌 | GUI가 STOP 전송, 다음 구동에 새 SW2 필요 |

MANUAL 정상 순서에서 DRIVE가 거부되지 않은 구간도 있었다. 그때 LOG OFF여서 D/MOTOR 최종
출력이 기록되지 않았고 실제 보드에서 PWM이 0이었는지 확정할 수 없었다.
컬러 센서 UNKNOWN은 MANUAL/MOTOR의 구동 차단 조건이 아니다.

실제 펌웨어 소스와 가짜 GPIO를 연결한 임시 PC 재현 결과:

| 입력/상태 | 적용 출력·가짜 하드웨어 관찰 |
|---|---|
| 정상 SW2 후 DRIVE 100 100 반복 | 허가 1, 래치 0, 적용 100/100, PWM 26/255, EN HIGH |
| STOP 후 SW2 없이 후진 | 허가 0, 적용 0/0 |
| 새 SW2 뒤 DRIVE -100 -100 | 적용 -100/-100, 역방향 PWM 26 |
| DRIVE 유지 시간 만료 | 적용 0/0 |
| DRIVE 200 200 | 적용 200/200, PWM 51 |

이는 MCU 실제 PWM 파형이나 회전 실측이 아니다. 정상 순서에서 무조건 출력을 막는 문제는 재현되지 않았다.
명령 100은 100%가 아닌 10%라 기동에 부족할 가능성이 있지만 원인으로 확인되지는 않았다.
센서 동기 처리가 80ms 이상 지연되면 독립 워치독이 출력을 끊을 수 있다.
약 1초 간격의 I2C 오류만으로 실제 호출 시간이나 미회전 원인을 확정하지 않는다.

### 독립 직접 PWM 시험과 마지막 재업로드

사용자가 기존 제어 없이 양쪽 모터를 저속으로 돌리는 별도 코드와 업로드를 명시적으로 요청했다.
`src/raw_motor_main.cpp`, 환경 `raw_motor_v2`를 추가했다. Arduino LEDC와 V2 핀 상수만 쓰고
기존 제어 모듈은 링크하지 않는다. PWM 초기화 실패 때만 EN LOW를 유지한다.

| 모터 | LPWM | RPWM | EN |
|---|---|---|---|
| 왼쪽 | GPIO42, 0 | GPIO41, 51/255 | GPIO40 HIGH |
| 오른쪽 | GPIO47, 0 | GPIO21, 51/255 | GPIO35 HIGH |

20kHz, 8bit, 고정 20%, 시작 부스트 없음. 기존 양수 명령과 같은 전기 입력이다.
실제 전진 방향은 아직 확인되지 않았다. 기존 경기용·벤치 제어 코드와 핀맵은 변경하지 않았다.

- 최초 빌드 성공: Flash 282329 bytes, RAM 18960 bytes.
- COM9 업로드 SUCCESS, 업로드 도구의 해시 검사 통과.
- 최초 업로드 후 약 5초 동안 아래 줄이 반복 수신됐다.

```text
RAW_MOTOR RUN duty=51/255 EN=1,1 PWM=0,51,0,51
```

EN은 GPIO 입력 판독, PWM은 LEDC 레지스터 값이다. 실제 파형·회전의 실측은 아니다.
이어 사용자가 “아무것도 확인하지 말고 다시 업로드만” 요청했고 동일 펌웨어를 COM9에 재업로드했다.
SUCCESS 확인 후 추가 시리얼 확인이나 회전 시험은 하지 않았다.
현재 보드에는 이 직접 PWM 펌웨어가 남아 있다.

호스트 시험의 소스 수집에서 스캐너와 직접 PWM 진입 파일을 제외해 setup/loop 중복을 방지했다.
`tools/run_bench_gui.cmd`는 현장 PC의 `C:\Python311\python.exe`로 GUI를 실행하는 보조 파일이다.
다른 PC에서는 해당 Python 경로 또는 일반 `python tools/bench_gui.py` 실행 환경을 맞춰야 한다.

## 남은 작업과 복귀

1. 현재 직접 PWM에서 실제 양쪽 바퀴 회전 여부를 사용자 관찰로 확인한다.
2. BAT와 멀티미터 일치, GPIO35의 부팅·리셋 파형, 실제 정방향·물리 SW1 차단은 미검증이다.
3. TCA/센서 구성 확인 후 네 센서의 번호와 실제 색 판정을 시험한다.
4. I2C 오류와 모터 명령 갱신 지연의 관계는 실제 시간 측정이 필요하다.
5. 벤치 복구는 모터 전원을 분리하고 `robot_bench_v2_manual`을 업로드한다.
   배터리 판정 후 `LOG ON → MODE MANUAL → SW2 → DRIVE` 순서이며 STOP 뒤 새 SW2가 필요하다.

```powershell
# 직접 PWM 시험: 업로드 후 자동 구동
platformio run -e raw_motor_v2 --target upload --upload-port COM9
# 모터 전원을 분리한 뒤 벤치 복구
platformio run -e robot_bench_v2_manual --target upload --upload-port COM9
# 모터 비활성 주소 스캐너
platformio run -e i2c_scanner_v2 --target upload --upload-port COM9
```
