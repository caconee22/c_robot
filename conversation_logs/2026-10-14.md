## 1. 동작 방식을 정하는 것

**권한 모드**는 도구를 실행할 때 사용자 승인을 얼마나 받을지 정해요. 한 번에 하나만 적용돼요.

| 모드 | 동작 |
|---|---|
| default | 파일 수정이나 명령 실행 전에 매번 확인 |
| acceptEdits | 파일 수정은 자동 승인, 명령 실행은 확인 |
| plan | 읽기만 하고 계획을 세운 뒤 승인을 받아 실행 |
| auto | 안전하다고 판단되는 작업은 자동 진행 |
| bypassPermissions | 확인 없이 진행. **지금 이 세션이 이 모드예요** |

**모델과 추론 강도(effort)**는 어떤 모델(Opus, Sonnet, Haiku 등)이 얼마나 깊게 생각할지 정해요. **Fast 모드**는 같은 Opus 모델로 출력만 빠르게 하는 옵션이에요.

**지침 파일**은 매 세션 시작 때 자동으로 읽혀서 규칙 역할을 해요.
- `CLAUDE.md`: 프로젝트 지침이에요. 이 저장소에서는 `@AGENTS.md`로 AGENTS.md를 불러와요.
- 메모리 폴더: 세션이 바뀌어도 남겨 둘 사실을 저장해요. 사용자 정보, 피드백, 프로젝트 정보 등이에요.

**설정(`settings.json`)**에는 허용·금지 명령 목록, 환경변수, 훅이 들어가요.

## 2. 기능을 늘리는 것

| 종류 | 형태 | 역할 | 예시 |
|---|---|---|---|
| **MCP 서버** | 외부 프로그램(서버) | Claude에게 **새 도구**를 붙여 줌 | 브라우저 조작, 화면 제어(computer-use), 터미널, Docs, Chrome 확장 |
| **스킬** | 지시문 묶음(`SKILL.md` + 스크립트) | 특정 작업의 **절차와 노하우**를 필요할 때 불러옴 | `pdf`, `xlsx`, `code-review`, `simplify` |
| **슬래시 커맨드** | `/이름` | 사용자가 직접 호출하는 단축 명령. 대부분 스킬이에요 | `/code-review`, `/init` |
| **훅(Hook)** | `settings.json`에 등록한 스크립트 | 특정 이벤트(도구 실행 전후, 프롬프트 입력 등)에 **하네스가 자동 실행** | "파일 저장 후 포맷터 실행" |
| **서브에이전트** | 별도 컨텍스트로 돌아가는 보조 에이전트 | 넓은 탐색이나 계획을 맡기고 결과만 받음 | `Explore`, `Plan`, `general-purpose` |
| **플러그인** | 위 요소들을 묶은 패키지 | 스킬, 커맨드, 훅, 에이전트, MCP 서버를 **한 번에 설치** | 팀 배포 플러그인 |
| **세션** | 독립된 대화 하나 | 다른 작업을 병렬로 진행. 로컬, 클라우드, SSH 모두 가능 | 사이드바의 다른 세션들 |

## 3. 서로의 관계

```
플러그인 ─┬─ 스킬 (= 슬래시 커맨드)
          ├─ 훅
          ├─ 서브에이전트 정의
          └─ MCP 서버 ──→ 도구(tool)

세션 ── 권한 모드 · 모델 · CLAUDE.md · 메모리 · settings.json 적용
  └─ Claude가 도구를 호출 → 권한 모드가 허용 여부를 판단 → 훅이 끼어들 수 있음
```

헷갈리기 쉬운 구분 세 가지예요.
- **MCP와 스킬**: MCP는 "손"을 하나 더 다는 것이고, 스킬은 "작업 매뉴얼"을 쥐여 주는 거예요. 스킬이 MCP 도구를 쓰는 방법을 알려 주는 경우도 많아요.
- **훅과 CLAUDE.md**: CLAUDE.md는 Claude가 읽고 따르는 규칙이라 해석의 여지가 있어요. 훅은 프로그램이 강제로 실행하는 거라 **"매번 반드시"** 필요하면 훅을 써야 해요.
- **서브에이전트와 세션**: 서브에이전트는 이 대화 안에서 잠깐 일하고 결과만 돌려줘요. 세션은 사용자가 직접 열어서 대화할 수 있는 별개의 작업이에요.

| 이렇게 말하면 | 불러오는 스킬 | 진행 방식 |
|---|---|---|
| "공격 FSM에 후진 회피 상태 추가하고 싶어" | brainstorming | 바로 코드를 짜지 않고 질문으로 요구사항과 설계를 먼저 정리 |

| "20mm에서 빨강이 검정으로 잡혀" | systematic-debugging | 추측으로 고치지 않고 재현, 원인 가설, 확인 순서로 진행 |
| "이 기능 구현해줘" | test-driven-development | 호스트 시험을 먼저 쓰고 구현 |
| "다 됐어?" | verification-before-completion | 빌드와 시험을 실제로 돌린 결과를 보여 준 뒤 완료 보고 |

```
/superpowers:systematic-debugging 후방 오른쪽 센서만 노랑 오판정
```

## 이 저장소에서의 주의점

## 2. 앞뒤 동시 위험색일 때 탈출 기동

## 먼저 확인해야 할 위험 3가지

**1. GPIO35·36·37 충돌 가능성 (가장 중요)**
ESP32-S3 모듈이 **옥탈 PSRAM 버전**(예: N16R8, N8R8)이면 GPIO35~37은 모듈 내부 메모리가 쓰고 있어서 외부에서 쓸 수 없어요. V2는 이 핀에 **오른쪽 모터 EN(35)**과 **오른쪽 엔코더(36, 37)**를 연결했어요. 기존 README에도 "YD-ESP32-S3의 플래시·PSRAM 사양 미확인"이 남아 있어요. 기판 조립 전에 모듈 표기를 꼭 확인해야 해요. 문제가 되면 펌웨어로는 해결할 수 없고 배선을 고쳐야 해요.

**2. GPIO19·20은 USB 핀이에요**
오른쪽 모터 전류(IS) 측정에 쓰여요. 이 핀을 아날로그로 쓰면 보드의 네이티브 USB 포트는 못 써요. UART 포트(CH343)로 업로드하면 문제없지만, 현장에서 USB 포트를 헷갈리지 않게 안내해야 해요.

**3. 아날로그 입력 일부가 ADC2예요**
IR6(13), 배터리(14), 오른쪽 전류(19, 20)가 ADC2 쪽이에요. Wi-Fi를 쓰지 않으면 동작하지만, 나중에 무선 기능을 넣으면 이 측정이 막혀요. 지금 설계는 Wi-Fi가 없어서 괜찮아요.

## 공식 입장
- **Espressif 문서:** 옥탈 플래시나 옥탈 PSRAM을 쓰면 GPIO33~37이 메모리 신호선(SPIIO4~7, SPIDQS)에 연결돼요. 그래서 R8 계열 칩에서는 이 핀을 다른 용도로 쓰는 걸 권장하지 않아요. ([Espressif GPIO 문서](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/peripherals/gpio.html))
- **YD-ESP32-S3 보드 제작사(VCC-GND) 자료:** N16R8에서 GPIO35·36·37은 내부 플래시·PSRAM 통신용으로 예약돼 외부에서 쓸 수 없다고 적혀 있어요. ([YD-ESP32-S3 저장소 정리](https://deepwiki.com/vcc-gnd/YD-ESP32-S3), [espboards.dev](https://www.espboards.dev/esp32/yd-esp32-s3/))
- **Espressif 포럼 직원 답변:** 프로그램에서 PSRAM을 쓰지 않으면 옥탈 PSRAM이 선택되지 않으니 그 핀을 쓸 수 있다고 했어요. 비공식 답변이라 직접 검증이 필요해요. ([esp32.com](https://esp32.com/viewtopic.php?p=133849))
